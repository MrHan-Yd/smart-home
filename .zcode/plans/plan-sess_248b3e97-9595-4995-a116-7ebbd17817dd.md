## P3 实现计划

覆盖三块：**多 HA 实例切换**、**本系统多步场景编排**、**组合设备（多 entity）**。新增依赖：无（后端复用 `coder/websocket`；前端无新库）。分 5 批推进。

---

### 批次 1 · 数据库迁移 `004_p3.sql`

```sql
-- 组合设备：devices 已有，扩展 meta 携带 member entity_ids 即可；不改表结构，
-- 但新增 device_members 显式表便于查询与 WS 跟踪
CREATE TABLE IF NOT EXISTS device_members (
    device_id  UUID NOT NULL REFERENCES devices (id) ON DELETE CASCADE,
    entity_id  TEXT NOT NULL,
    role       TEXT NOT NULL DEFAULT 'member',  -- primary|member
    sort_order INT  NOT NULL DEFAULT 0,
    PRIMARY KEY (device_id, entity_id)
);
CREATE INDEX IF NOT EXISTS idx_device_members_entity ON device_members (entity_id);

-- 多步场景：本系统存步骤，一键串行执行
CREATE TABLE IF NOT EXISTS scenarios (
    id         UUID PRIMARY KEY,
    home_id    UUID NOT NULL REFERENCES homes (id) ON DELETE CASCADE,
    user_id    UUID NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    name       TEXT NOT NULL,
    icon       TEXT,
    room_id    UUID REFERENCES rooms (id) ON DELETE SET NULL,
    sort_order INT  NOT NULL DEFAULT 0,
    enabled    BOOLEAN NOT NULL DEFAULT true,
    last_run_at TIMESTAMPTZ,
    run_count  INT  NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_scenarios_home ON scenarios (home_id, sort_order, name);

CREATE TABLE IF NOT EXISTS scenario_steps (
    id          UUID PRIMARY KEY,
    scenario_id UUID NOT NULL REFERENCES scenarios (id) ON DELETE CASCADE,
    sort_order  INT  NOT NULL DEFAULT 0,
    device_id    UUID NOT NULL REFERENCES devices (id) ON DELETE CASCADE,
    action      TEXT NOT NULL,
    params      JSONB NOT NULL DEFAULT '{}'::jsonb,
    delay_ms    INT  NOT NULL DEFAULT 0,   -- 前置等待
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (scenario_id, sort_order)
);
CREATE INDEX IF NOT EXISTS idx_scenario_steps ON scenario_steps (scenario_id, sort_order);

-- ha_instances 切换：is_active 已存在；加唯一部分索引保证每 home 至多一个 active
CREATE UNIQUE INDEX IF NOT EXISTS idx_ha_instances_active
    ON ha_instances (home_id) WHERE is_active = true;
```

`devices.meta` 已是 JSONB，组合设备仍用 `devices` 行承载（域取主 entity 的 domain 或 `group`），`device_members` 表显式记录成员。这样 deviceView/控制/历史/analytics 主链路改动最小。

### 批次 2 · 组合设备（后端 + 前端）

**后端**
- `module/device/repo.go`：新增 `Members` 相关方法
  - `SetMembers(ctx, deviceID, []Member)` —— 事务内删旧+插新；`role` 首个为 `primary`
  - `MembersOf(ctx, deviceID) ([]Member, error)`
  - `EntityIDsByDevice(ctx, deviceID) ([]string, error)`（用于 deviceView 与 hub 跟踪）
  - `ListComposites(ctx, userID)` / 复用 `List` + 判 meta
- `httpserver/handlers_device.go`：
  - 新增 `POST /api/v1/devices/composite` `{ entity_ids: []string, name?, room_id?, primary_entity_id? }`：校验所有 entity 在 HA 存在；创建一条 device（domain = primary 的 domain，`meta.kind="composite"`），写 `device_members`；返回 composite deviceView。
  - `deviceView`：若 `meta.kind=="composite"`，附加 `entity_ids: [...]`、`members: [{entity_id, state, available}]`（批量查 HA states），`primary_display` 聚合（任一 on → on）。
  - `handleDeviceAction`：组合设备 → 遍历 members，逐个 `CallService`（同 action；对 scene/script 仍单按钮）；审计记录主 device_id。
  - `handleListDevices`/`handleDiscoverEntities`：发现页 `already_added` 判断需把 composite 成员也算作已添加（`EntityIDsByHome` 已覆盖成员 entity_id 会被双计，需在 discover 中去重：成员 entity_id 标 `already_added` 且 `member_of_composite`）。
- `server.go`：`refreshHubTracking` 改用「devices 的所有 entity_id（含成员）」集合——新增 `EntityIDsByUserWithMembers`；WS `recordTelemetry` 命中 member 时找到所属 composite 一并刷新 deviceView 推送（hub 订阅回调里按 entity 反查 composite device id）。
- 路由注册 `POST /api/v1/devices/composite`。

**前端**
- `types/api.ts`：`DeviceView` 增 `entity_ids?: string[]`、`members?: {entity_id; state; available}[]`、`meta?: {kind?: string}`。
- `api/index.ts`：新增 `createCompositeDevice({entity_ids, name?, room_id?})` → `POST /api/v1/devices/composite`。
- `lib/device.ts`：`isComposite(d)` = `d.meta?.kind==='composite' || (d.entity_ids?.length ?? 0) > 1`；`compositeIsOn(d)` 聚合 members；`domainEmoji` 加 `group`→⛦。
- `AddDeviceView.vue`：已有 `selected: Set<string>`，新增「组合添加」按钮（选中 ≥2 时启用）→ 调 `createCompositeDevice`。
- `DeviceCard.vue` / `DeviceControls.vue`：组合设备卡片显示成员数徽章 + 单「执行」按钮（对所有可控成员执行 turn_on/turn_off/toggle）；详情页列出成员表（entity_id · state），可对单个成员操作。

### 批次 3 · 本系统多步场景编排（后端 + 前端）

**后端** `module/scenario/repo.go`（新）+ `httpserver/handlers_scenario.go`（新）
- `GET /api/v1/scenarios` → 列表（含 steps 概要）
- `POST /api/v1/scenarios` `{name, icon?, room_id?, steps: [{device_id, action, params?, delay_ms?}]}`
- `GET /api/v1/scenarios/{id}`
- `PATCH /api/v1/scenarios/{id}`（改 name/icon/room/sort；steps 走专用端点）
- `PUT /api/v1/scenarios/{id}/steps` —— 全量替换步骤
- `DELETE /api/v1/scenarios/{id}`
- `POST /api/v1/scenarios/{id}/run` —— 串行执行：逐 step 查设备归属校验 → `ResolveAction` → `CallService` → 按 `delay_ms` sleep；任一步失败则记录并继续（容错，结果返回每步 success/error）；写 `run_count++`、`last_run_at=now()`；复用 `actionlog` 审计每步。
- 路由注册于 `server.go`，`s.scen = scenario.NewRepo(db)`。

**前端**
- `types/api.ts`：`Scenario`、`ScenarioStep` 类型。
- `api/index.ts`：`fetchScenarios`、`createScenario`、`fetchScenario`、`patchScenario`、`replaceScenarioSteps`、`deleteScenario`、`runScenario`。
- `views/ScenariosView.vue`（新，路由 `/scenarios`，侧栏「场景」入口 ✦）：场景卡片列表 + 新建/编辑抽屉。编辑器：步骤列表（每步选设备→根据设备 capabilities 给出可选 action 下拉→参数表单→延迟输入），可拖拽排序。顶部「立即执行」按钮调 `runScenario`，显示每步结果 toast。
- `router/index.ts` + `AppShell.vue` nav 加 `/scenarios`。

### 批次 4 · 多 HA 实例切换（后端 + 前端）

**后端**
- `module/hainstance/repo.go`：新增 `Activate(ctx, homeID, id)` —— 事务内 `UPDATE ha_instances SET is_active=false WHERE home_id=$1` + `UPDATE ... SET is_active=true WHERE id=$2 AND home_id=$1`；受 `idx_ha_instances_active` 保护。
- `httpserver/handlers_ha.go`：新增 `POST /api/v1/ha/instances/{id}/activate` → 调 `Activate` + `reloadActiveHA` + `refreshHubTracking`（重连 WS）。
- `server.go`：路由注册；`HAStatus` 接口附带 `active_instance_id`（查 `hainst.Active`）。

**前端**
- `api/index.ts`：`activateHAInstance(id)` → `POST /api/v1/ha/instances/{id}/activate`；`HAInstance` 移入 `types/api.ts` 并加字段一致化。
- `SettingsView.vue`：每实例行加「启用」按钮（`is_active` 时禁用为「活跃」徽章）；点击后 `activateHAInstance` → `refreshHA()`。
- `useHA.ts`：`refresh` 后顺带刷新 instances 列表（或在 SettingsView 本地刷新即可，避免全局耦合）。
