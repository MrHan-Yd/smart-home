# 任务包：电耗与功率（含入库）

> 依据：[电耗与功率.md](./电耗与功率.md) · [数据库设计.md](./数据库设计.md)  
> 状态：**待办** · 更新 2026-07-24  
> **产品约束：统计分析必须入库，分析 API 不长期直扫 HA。**

---

## 背景

- HA 可提供 `power` / `energy` 类 sensor。  
- HA history 默认保留短、且依赖 HA 在线 → **本系统增量同步进 PG**，再做曲线与汇总。

---

## 任务列表

### A. 识别与展示增强（小）

| 项 | 验收 |
|----|------|
| 发现/设备视图识别 `device_class=power\|energy` | 展示「功率/电量」+ 单位 |
| （可选）总览当前总功率 | 已纳入 power 求和（单位统一） |
| 无实体空态 | 引导去 HA 加集成 |

### B0. 入库与同步（**统计分析前置 · 必须**）

| 项 | 验收 |
|----|------|
| 执行 `migrations/002_telemetry_energy.sql` | 三表存在 |
| HA history 客户端 | 可按 entity + 时间拉取 |
| 同步 worker / `POST .../telemetry/sync` | 已纳入 power/energy → 写入 `telemetry_samples` |
| `sync_cursors` 增量 | 二次同步不重复炸表（UNIQUE 冲突忽略） |
| 单位归一 | power→W、energy→kWh（或写清 unit 字段） |
| 失败可观测 | cursor.last_error / 日志（无 token） |

### B1. 曲线读库（P1）

| 项 | 验收 |
|----|------|
| `GET .../history` 或 telemetry 查询 | **默认读 `telemetry_samples`** |
| 库无数据时 | 可触发一次 sync 或明确 404/空 + 提示同步 |
| 前端 ECharts | 功率/电量至少一种 |

### C. 日汇总与分析 API（P2）

| 项 | 验收 |
|----|------|
| 汇总任务 | 写入/更新 `daily_device_stats.energy_kwh` + `energy_source` |
| energy 差分优先 | 回零有保护 |
| 仅 power 时 | 积分估算并标记 `power_integral` |
| `GET /analytics/*` | **读日汇总表**，不扫 HA |
| 排行 / KPI / 降级文案 | 无数据可提示 |

### D. 组合设备 / 电费（P3，可选）

开关 + 功率/电量绑定；电费单价配置。

---

## 推荐排期

```
A 展示 → B0 入库同步 → B1 曲线 → C 日汇总分析 → D 可选
```

当前若仍在做登录/设备控制联调：表可先执行 002；**worker 与分析实现排在控制稳定后**，但文档与 schema **已按入库定稿**。

## 依赖

| 依赖 | 说明 |
|------|------|
| HA 实体 | 无 power/energy 则只能空态 |
