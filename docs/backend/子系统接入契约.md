# 子系统接入契约（IdP 就绪清单）

> 目标：你做业务子系统时，**只写子系统侧代码**，认证中心协议稳定可对接。  
> 本文是「接口契约 + 必对字段」；操作步骤见 [子系统接入说明.md](./子系统接入说明.md)。

---

## 0. 核心原则（必读）

**统一认证中心是唯一身份源（IdP）。子系统不颁发、不伪造 Access / Refresh / ID Token。**

| 角色 | 做什么 | 不做什么 |
|------|--------|----------|
| **统一认证中心** | 登录、发 code、签发/刷新/吊销 JWT、JWKS、userinfo | — |
| **子系统** | 跳转登录、用 code **向认证中心换票**、**校验** JWT、建**本地业务会话**、按需调 refresh | **自己签发** access/refresh；自建账号密码登录顶替 SSO；改 JWT claims |

```
用户 → 子系统（未登录）
     → 302 认证中心 /oauth/authorize
     → 未登录：302 → {APP_BASE_URL}/login?redirect=/oauth/authorize?...
     → 用户登录（redirect 优先）
     → 首次访问该 client（或 scope 扩权）：302 → /consent 授权请求页
     → 用户点「授权」→ 写 user_consents → 发 code
     → 302 子系统 redirect_uri?code=&state=
     → 子系统服务端 POST 认证中心 /oauth/token  （唯一发 token 的地方）
     → 子系统保存 token / 建本地 session
     → 业务 API：Bearer access 或本地 session（session 仅子系统内部，不是新 IdP）
```

说明：

1. **Token 只由认证中心 `/oauth/token` 产生**（含 refresh 换新票）。  
2. 子系统可以有 **自己的 session cookie**（记 `sub`、缓存 access），那是业务会话，**不是**再发一套全局 JWT。  
3. 子系统之间互调：带认证中心发的 Bearer，或走服务端已换好的 token；**不要**子系统 A 给子系统 B 签 token。  
4. 过期：子系统调认证中心 **refresh**（无感刷新写在子系统），失败则重新走 authorize。  
5. **授权同意页**是认证中心 IdP 侧「用户是否把 scope 授给该 client」，**不是**子系统本地开户。子系统是否用 `sub` 自动建业务账号由子系统自行决定。

## 1. 环境约定

| 变量 / 概念 | 说明 | 联调示例 |
|-------------|------|----------|
| `AUTH_BASE` | 浏览器访问 **authorize / token / jwks** 的根（须能打到 auth-service） | 开发：`http://127.0.0.1:5173`（Vite 代理 `/oauth`）或 `http://127.0.0.1:3000`；网关：`http://localhost` |
| `APP_BASE_URL` | OIDC `issuer`；未登录 302 登录页根 | 开发前端：`http://127.0.0.1:5173`（**勿混用 localhost 与 127.0.0.1**，Cookie 不同源） |
| 登录页 | 前端路由 `/login` | 须与 `APP_BASE_URL` 同源可达 |
| 同意页 | 前端路由 `/consent` | 需登录；首次授权该 client 时由 authorize 302 进入 |
| JWT | RS256；JWKS：`{AUTH_BASE}/jwks.json` | 校验 `iss` == `APP_BASE_URL`（无尾斜杠） |

**重要：**

1. 子系统走 OAuth 时，用户浏览器要能打开登录页；只起后端 `:3000` 不起前端时，`APP_BASE_URL` 指向 `:3000` 会 404 —— 请起 `frontend` 或网关挂 auth-web。  
2. 开发态 Vite 已代理 `/oauth`、`/jwks.json`、`/.well-known` → `:3000`；子系统可把 `AUTH_BASE` 设为 `http://127.0.0.1:5173`，与登录页同源，Cookie/`sid` 一致。  
3. **切换系统**建议跳 `{APP_BASE_URL}/select-system`（或根路径 `/`，已登录会进系统选择），**不要**只跳 `/login` 且清 Cookie。

## 2. 端点一览（稳定）

| 用途 | 方法 | 路径 |
|------|------|------|
| 授权 | GET | `/oauth/authorize` |
| 用户同意 / 拒绝 | POST | `/oauth/consent`（浏览器已登录 Session；前端同意页调用） |
| 换票 / 刷新 | POST | `/oauth/token`（`application/x-www-form-urlencoded`） |
| 吊销 | POST | `/oauth/revoke` |
| 自省 | POST | `/oauth/introspect` |
| 用户信息 | GET | `/oauth/userinfo`（`Authorization: Bearer`） |
| 公钥 | GET | `/jwks.json` |
| 发现文档 | GET | `/.well-known/openid-configuration` |
| 注册客户端 | POST | `/admin/clients`（需管理员登录） |

网关若反代，路径保持上述前缀。开发前端：`/api` → 业务 API；**浏览器跳转** `/oauth/authorize` 走 Vite `/oauth` 代理到 auth-service（勿用 SPA history 假路由）。子系统服务端换票可直连 `http://127.0.0.1:3000`。

## 3. Access Token Claims（子系统验签用）

| Claim | 含义 |
|-------|------|
| `sub` | 用户 UUID（v7 字符串） |
| `iss` | `APP_BASE_URL` |
| `aud` | **client_id**（字符串，非内部 uuid） |
| `exp` / `iat` | 过期 / 签发时间（unix 秒） |
| `jti` | 唯一 id，吊销黑名单用 |
| `scope` | 空格分隔，如 `openid profile email` |
| `token_use` | 可选，`access` |

算法：**仅 RS256**。`kid` 在 JWT header，对照 JWKS。

**推荐校验顺序：**

1. 拉取并缓存 JWKS（如 10 分钟）  
2. 验签 + `alg=RS256`  
3. `iss` 精确等于配置的 issuer（见 §1）  
4. `aud` 等于本系统 `client_id`（或包含）  
5. `exp` 未过期（允许少量 clock skew，如 60s）  
6. （可选）调 introspect 看是否被吊销  

> **关于 `iss`：** 校验应精确等于认证中心 `APP_BASE_URL`（无尾斜杠）。若 IdP 实际 `iss` 与子系统配置不一致，**应统一改 IdP `APP_BASE_URL`**，而不是在子系统侧放宽成「接受任意 iss」；开发期确需过渡时，子系统最多接受 `{AUTH_BASE}` 作为候选 iss，并记 TODO 尽快收敛。

## 4. Token 响应（RFC）

```json
{
  "access_token": "...",
  "token_type": "Bearer",
  "expires_in": 900,
  "refresh_token": "...",
  "id_token": "...",
  "scope": "openid profile email"
}
```

| 字段 | 说明 |
|------|------|
| `expires_in` | access 秒数，子系统应用此值做无感刷新阈值 |
| `refresh_token` | **轮换**：每次 refresh 后旧值立即失效 |
| `id_token` | 含 openid 时返回；展示用户信息可用，API 鉴权用 access |

### 4.1 Token 寿命策略（IdP 侧配置，子系统不可绕过）

| 票 | IdP 建议寿命 | 子系统侧行为 |
|----|--------------|--------------|
| **access_token** | **短**（300～900s，默认 `ACCESS_TOKEN_TTL_SECS=900`） | **只信 `expires_in`**；将过期时由子系统单飞 refresh；**不得**自缩短或延长 |
| **refresh_token** | **长**（7～30d，默认 `REFRESH_TOKEN_TTL_SECS=2592000`） | 仅服务端持有；轮换 + 复用吊销家族 |
| 本地业务 session | 子系统自定，建议最长对齐 refresh 寿命 | 子系统内部会话，**不是**新 IdP |

**要点：**

1. 子系统**不能改短 IdP 已签发的 access**——要调短请改 IdP 的 `ACCESS_TOKEN_TTL_SECS`。  
2. access 续期是**子系统**职责（无感刷新写在子系统），IdP 只保证 `/oauth/token` refresh 行为稳定。  
3. refresh 触发阈值建议：access 剩余 < 60s（与 exp 校验 clock skew 一致）即单飞 refresh。

## 5. 刷新（子系统实现无感刷新时）

```http
POST {AUTH_BASE}/oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=refresh_token
&refresh_token={当前 refresh}
&client_id={client_id}
&client_secret={client_secret}
```

**规则（必须遵守）：**

1. **仅服务端**持有 `client_secret` 与 refresh（浏览器 SPA 用 PKCE + 后端 BFF 更安全）  
2. 同一 refresh **不要并发**刷新（加锁；失败后用新 token）  
3. 若返回 token 已吊销 / 复用检测失败 → **清本地会话，重新走 authorize**  
4. 建议：access 剩余 &lt; 60s 或 API 401 时再 refresh，再重试原请求一次  

IdP **不**替子系统自动刷；只保证本接口行为稳定。

### 5.1 子系统会话建议（非强制，但能减少联调摩擦）

子系统本地业务 session 建议采用「三段式」：

| 机制 | 建议值 | 说明 |
|------|--------|------|
| 空闲超时 | 如 2h | 无请求即踢出并尝试 revoke，**即使 refresh 未过期** |
| 最长 TTL | 对齐 refresh（如 7d） | Redis 键寿命上限，防止无限续期 |
| Refresh 触发 | access 剩余 < 60s 单飞 | 与 exp 校验 clock skew 一致 |

- access 续期**单飞**（全局锁），失败清本地会话 → 重新 authorize。  
- 「切换系统」**只**清本地 session，不调 IdP logout；「登出」可再调 revoke。  
- refresh 失败（已吊销 / 复用检测失败）→ 必须清会话重登，**不要**用旧 refresh 重试。

## 6. 授权请求参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `response_type` | 是 | 固定 `code` |
| `client_id` | 是 | 须在管理台 `oauth_clients` 已注册且 `active` |
| `redirect_uri` | 是 | **与注册白名单完全一致**（含 path、端口、尾斜杠） |
| `scope` | 否 | 默认 `openid profile`；可用 `email` `phone` `offline_access` |
| `state` | 强烈建议 | CSRF；回调原样校验 |
| `nonce` | 建议 | 进 id_token |
| `code_challenge` | PKCE 时 | S256 |
| `code_challenge_method` | PKCE 时 | `S256` |
| `consent` | 否 | 内部用；同意页确认后带 `consent=1` 回 authorize |

### 6.1 authorize 行为（登录 / 同意）

| 条件 | 响应 |
|------|------|
| `client_id` 未知 / 禁用 | OAuth 错误 `invalid_client`（**不会**自动注册子系统） |
| `redirect_uri` 不在白名单 | `invalid_request` |
| 未登录（无 Session Cookie `sid`） | 302 → `{APP_BASE_URL}/login?redirect=` + urlencode(**相对路径** `/oauth/authorize?...`) |
| 已登录，**无**对该 client 的有效同意（或本次 scope 超出已同意） | 302 → `{APP_BASE_URL}/consent?client_id&client_name&redirect_uri&scope&state&...` |
| 已登录且已有覆盖本次 scope 的同意 | 直接发 code → 302 `redirect_uri?code=&state=` |
| 用户在同意页 **拒绝** | 302 `redirect_uri?error=access_denied&state=`（经 `POST /oauth/consent`） |
| 用户在同意页 **授权** | 写入 `user_consents` → 发 code → 302 子系统回调 |

**同意记录：** 表 `user_consents`（迁移 `006_user_consents.sql`），键为 `(user_id, client_id)`，存已授 scope；同一用户再次访问同一 client 且 scope 未扩权时**不再弹同意页**。

**与「子系统本地账号」无关：** 认证中心不创建业务系统用户；只认认证中心已有用户（管理台建号）。子系统用 `sub` / userinfo 自行决定是否本地开户。

### 6.2 登录后回跳子系统（子系统侧无需额外处理）

1. 子系统未登录 → authorize → 登录页带 `redirect=/oauth/authorize?...`（含原 `client_id` / `redirect_uri` / PKCE / `state`）。  
2. 用户登录成功 → 前端**优先**整页跳转该 `redirect`（`window.location`，不走 SPA 假路由）。  
3. authorize →（同意页）→ code → 子系统 `redirect_uri`。  
4. 因此：**从子系统进来登录的用户，登录后会回到该子系统**，不会落到「系统选择」除非没有 `redirect`。

### 6.3 切换系统 / SSO 会话

- 认证中心 Session 为 HttpOnly Cookie（默认名 `sid`，`SameSite=Lax`）。  
- 从子系统跳回认证中心时：请打开 `{APP_BASE_URL}/` 或 `/select-system`；前端会用 Cookie 调 `/auth/me` 恢复登录态。  
- 若跳到登录页却已登录，会自动进 `/select-system`。  
- 子系统「切换系统」**不要**调用认证中心 logout，否则会清 SSO。

## 8. 子系统最小实现清单（你做子系统时勾）

- [ ] 确认：**不自签 access/refresh**；票只来自 `{AUTH_BASE}/oauth/token`  
- [ ] 配置 `AUTH_BASE`、`client_id`、`client_secret`、`redirect_uri`、`issuer`  
- [ ] 管理台已注册 client，`redirect_uri` 精确匹配  
- [ ] 未登录 → authorize（state + PKCE）；**不要**自己画登录页顶替 SSO  
- [ ] 回调：校验 state → **向认证中心换 token** → 存 session / token  
- [ ] （可选）用 `sub` 做本地用户 upsert；**不是**认证中心职责  
- [ ] API：`Authorization: Bearer` + **JWKS 校验认证中心 JWT**（或仅信已换票后的本地 session）  
- [ ] 无感刷新：401 或临近过期 → 调认证中心 refresh（单飞）→ 重试  
- [ ] 登出：清本地 session + 可选 revoke；「切换系统」跳 `{APP_BASE_URL}/select-system`  
- [ ] 生产：HTTPS、secret 不进前端仓；Cookie 域名与 `APP_BASE_URL` 一致  

联调脚本：`docs/examples/subsystem-integration/`。
