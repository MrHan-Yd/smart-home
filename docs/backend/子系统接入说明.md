# 子系统接入说明（P1）

> 业务系统如何接入统一认证中心（OAuth2 授权码 + OIDC）。  
> **契约与 Claims / 刷新规则：** [子系统接入契约.md](./子系统接入契约.md)  
> **联调脚本（无业务工程）：** `docs/examples/subsystem-integration/`  
> 演示客户端：`demo_app`（迁移 `003_seed_demo_client.sql`）

---

## 0. 原则：子系统不颁发 Token

| 谁 | 职责 |
|----|------|
| **统一认证中心** | **唯一**负责认证与发票：登录、`/oauth/token` 签发 access / refresh / id_token、刷新、吊销、JWKS |
| **子系统** | 注册为 OAuth **客户端**；引导用户去认证中心登录；**用 code 向认证中心换 token**；用 JWKS **校验** token；可建**本地业务 session**（缓存 `sub` 等） |

**禁止：**

- 子系统自己用对称密钥 / 私钥签发「全局」Access Token 给前端或其它系统  
- 子系统维护独立账号密码体系替代 SSO（本架构下用户只在认证中心登录）  
- 把 `client_secret` 放到浏览器  

**允许：**

- 子系统服务端 session（HttpOnly Cookie），里面存从认证中心换来的 token 或仅存 `user_id`  
- API 鉴权：校验认证中心 JWT，或只认已建立的本地 session（session 建立时必须已验证过来自认证中心的 token）

详见契约文档 §0。

## 1. 注册客户端

由认证中心管理员调用（或 SQL 种子）：

`POST /admin/clients`

```json
{
  "name": "业务系统 A",
  "redirect_uris": ["https://app-a.example.com/oauth/callback"],
  "allowed_grants": ["authorization_code", "refresh_token"],
  "pkce_required": true,
  "confidential": true,
  "scopes": ["openid", "profile", "email"]
}
```

**响应中只会展示一次 `client_secret`，请妥善保存。**

记下：

| 项 | 示例 |
|----|------|
| `client_id` | `app_a` |
| `client_secret` | `***` |
| 授权地址 | `{AUTH_BASE}/oauth/authorize` |
| Token 地址 | `{AUTH_BASE}/oauth/token` |
| JWKS | `{AUTH_BASE}/jwks.json` |
| Issuer | `{AUTH_BASE}`（与 `APP_BASE_URL` 一致） |

可选：在认证中心配置 `system_routes`，登录后出现在系统选择页。

## 2. 登录跳转（前端 / 网关）

用户访问子系统受保护页且无本地会话时：

```
302 → {AUTH_BASE}/oauth/authorize
  ?response_type=code
  &client_id={client_id}
  &redirect_uri={url_encode(回调地址)}
  &scope=openid%20profile%20email
  &state={随机串}
  &code_challenge={S256}
  &code_challenge_method=S256
```

- `state` 存入子系统 session/cookie，回调时校验防 CSRF  
- 建议 **PKCE**（SPA/公网客户端必开；机密客户端也推荐）  
- `client_id` 必须已在认证中心注册，否则 `invalid_client`（**不会**自动创建客户端或用户）

### 2.1 用户在认证中心侧会经历什么

```
authorize
  ├─ 未登录 → /login?redirect=/oauth/authorize?...
  │            └─ 登录成功 → 整页回到 authorize（不会丢 redirect）
  ├─ 已登录 + 首次访问该 client（或 scope 扩权）
  │            → /consent（授权请求：openid / profile / email …）
  │                 ├─ 授权 → 记 user_consents → 发 code → 子系统回调
  │                 └─ 拒绝 → 子系统回调 ?error=access_denied&state=
  └─ 已登录 + 已同意 → 直接发 code → 子系统回调
```

- **同意页** = 用户是否把身份/资料 scope 授给该 OAuth 客户端（表 `user_consents`，迁移 `006_user_consents.sql`）。  
- **不是**「子系统没注册账号」：认证中心用户由管理员创建；子系统本地是否用 `sub` 开户由业务系统决定。  
- 再次进入同一 client 且 scope 未增加：**不再弹**同意页。

### 2.2 登录后是否回到原子系统

**会。** 未登录时 IdP 把完整 authorize 路径放在 `login?redirect=` 里；登录成功前端优先 `window.location` 打开该路径，再走同意/发 code，最终 302 到你的 `redirect_uri`。

### 2.3 切换系统（保留 SSO）

子系统提供「切换系统」时，建议：

```
location.href = "{APP_BASE_URL}/select-system"
// 或 "{APP_BASE_URL}/"（已登录会进系统选择）
```

- **不要**调用 `POST /auth/logout`（会清认证中心 Session）。  
- 仅清子系统本地 session 即可；再进其它系统时走 authorize，已登录则跳过登录页。

## 3. 回调换 Token（票只在这一步由认证中心发出）

回调两种结果：

| 查询参数 | 含义 |
|----------|------|
| `code` + `state` | 用户已授权（或已有同意） |
| `error=access_denied` + `state` | 用户在同意页点了拒绝 |

1. 校验 `state`；若 `error` 则提示用户并停在子系统  
2. **子系统服务端**请求认证中心（勿在浏览器暴露 `client_secret`）—— **Token 由认证中心生成并返回，子系统只接收与存储**：

```http
POST {AUTH_BASE}/oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code={code}
&redirect_uri={与授权时完全一致}
&client_id={client_id}
&client_secret={client_secret}
&code_verifier={pkce_verifier}
```

3. 保存认证中心返回的 `access_token` / `refresh_token` / `id_token`  
4. 建立子系统**本地业务会话**（可选；会话内容来自上述 token 校验结果，不是子系统自签 JWT）

> **三处必须完全一致：** ①认证中心客户端 `redirect_uris` 白名单 ②子系统 `OAUTH_REDIRECT_URI` ③浏览器 authorize 请求里的 `redirect_uri` 参数。含 path、端口、尾斜杠，任一不一致都会 `invalid_request` / `redirect_uri not allowed`。

## 4. 校验 Access Token

### 方式 A：本地 JWT 校验（推荐）

1. 缓存 `GET {AUTH_BASE}/jwks.json`
2. 校验：签名、`iss`、`aud`（或 client）、`exp`、`nbf`
3. 从 claims 取 `sub`（用户 UUID v7）等

### 方式 B：自省

```http
POST {AUTH_BASE}/oauth/introspect
Content-Type: application/x-www-form-urlencoded

token={access_token}
&client_id=...
&client_secret=...
```

看 `active: true` 再放行。适合需要即时吊销感知的场景。

### 用户资料

```http
GET {AUTH_BASE}/oauth/userinfo
Authorization: Bearer {access_token}
```

### 开发期降级：JWKS 失败时用 userinfo 兜底

生产**必须**用 JWKS 本地验签。开发期若 JWKS 暂不可达（密钥未配 / 网络受限），可临时调 `/oauth/userinfo` 取 `sub` 建 session，并记 TODO 切回 JWKS。建议子系统提供类似 `STRICT_JWT=false`（dev） / `true`（prod）的开关，避免降级逻辑泄漏到生产。

## 5. 刷新与登出

**刷新：**

```
grant_type=refresh_token
&refresh_token=...
&client_id=...
&client_secret=...
```

刷新后旧 refresh 失效（轮换）；勿并发用同一 refresh。

**子系统登出：**

1. 清本地会话  
2. 可选：`POST {AUTH_BASE}/oauth/revoke` 吊销 token  
3. 可选：引导用户打开认证中心 `POST /auth/logout` 做 SSO 全局登出  
4. **切换系统** ≠ 登出：见 §2.3  

> **全局登出与失效窗口：** 认证中心做 SSO 全局登出后，子系统**不会秒断**——已签发的 access 在其短 TTL 内仍可用，子系统要等下次 refresh 失败或本地空闲超时才感知到。为缩短该窗口，**认证中心全局登出应同步吊销该用户的 refresh 家族**（`POST /auth/logout?all=true` 已会清全部会话；refresh 吊销走 `/oauth/revoke`），否则子系统可能在 access 窗口内继续放行。

## 6. 后端伪代码（机密客户端）

```text
function requireLogin(req):
  if not session.user:
    state, verifier = random()
    save(state, verifier)
    redirect authorize_url(state, challenge(verifier))

function callback(code, state, error):
  assert state == saved.state
  if error == "access_denied":
    show "用户拒绝授权"; return
  tokens = post_token(code, saved.verifier)   // 只向认证中心换票
  claims = verify_jwt(tokens.access_token, jwks)
  session.user = claims.sub
  // 可选：本地用户 upsert(sub, userinfo)
  session.tokens = tokens
  redirect home

function switchSystem():
  clearLocalSessionOnly()
  redirect APP_BASE_URL + "/select-system"
```

## 7. 安全清单

- [ ] `redirect_uri` 精确匹配白名单（含 path）
- [ ] 使用 HTTPS 生产环境
- [ ] `client_secret` 仅服务端持有
- [ ] PKCE + `state`
- [ ] Access 短有效期，API 带 Bearer
- [ ] 校验 `iss` / 签名算法（仅 RS256）
- [ ] 不要在 URL 日志中打印 code/token
- [ ] 生产 Cookie：`COOKIE_SECURE=true`，域名与登录页一致（`localhost` ≠ `127.0.0.1`）

## 8. 联调最小 curl

```bash
# 1) 浏览器完成 authorize（必要时登录 + 同意页）拿到 code 后：
curl -s -X POST "$AUTH/oauth/token" \
  -d "grant_type=authorization_code" \
  -d "code=$CODE" \
  -d "redirect_uri=$REDIRECT" \
  -d "client_id=$CID" \
  -d "client_secret=$SEC" \
  -d "code_verifier=$VERIFIER"

# 2) userinfo
curl -s "$AUTH/oauth/userinfo" -H "Authorization: Bearer $ACCESS"
```

更完整接口见 `docs/backend/接口/接口设计.md` 与 `openapi.yaml`。

## 9. 接子系统前确认（IdP 已就绪）

- [ ] 迁移 `001`～`003` 已执行；**`006_user_consents.sql` 已执行**（同意页依赖）  
- [ ] `demo_app` 存在或已在管理台注册客户端；`redirect_uri` 与子系统一致  
- [ ] JWT 密钥存在；`APP_BASE_URL` 与登录页一致（开发常用 `http://127.0.0.1:5173`）  
- [ ] 浏览器能完成：**authorize → 登录 →（首次）同意 → code 回调**  
- [ ] 再次 authorize 同一用户同一 client：**跳过同意页** 直接 code  
- [ ] 拒绝授权：回调带 `error=access_denied`  
- [ ] curl：`exchange-token` → `userinfo` → `refresh-token` 成功  
- [ ] 子系统按[契约](./子系统接入契约.md)实现 JWT 校验与 refresh 单飞  

**无感刷新写在子系统**，认证中心只保证 `/oauth/token` 行为稳定。

## 10. 常见对接错误对照

| 现象 | 常见原因 | 处理 |
|------|----------|------|
| `invalid_client` | `client_id` 未注册 / 被禁用 / `client_secret` 错 | 管理台核对 client；secret 用 `rotate-secret` 重发 |
| `invalid_request` / `redirect_uri not allowed` | 白名单与请求或 `OAUTH_REDIRECT_URI` 不一致 | 三处统一（见 §3），含 path、端口、尾斜杠 |
| `invalid_grant` / `code expired` | 授权码超 300s 或已用过 | 重新走 authorize；code 一次性 |
| `error=access_denied` 回调 | 用户在同意页拒绝 | 提示用户并停子系统；非 bug |
| 回调无后端日志 | 请求未到子系统 `redirect_uri` | 确认白名单指向子系统后端在跑 |
| 登录后又像未登录 | `localhost` 与 `127.0.0.1` 混用，Cookie 不同源 | 统一用 `127.0.0.1`（或生产统一域名） |
| JWKS 验签失败 | `iss` ≠ `APP_BASE_URL`；公钥未更新；kid 不匹配 | 对齐 `APP_BASE_URL`；刷新 JWKS 缓存；开发期可临时用 userinfo 兜底（见 §4） |
| 同意页反复弹 | `user_consents` 未落（迁移 `006` 未执行）或 scope 扩权 | 执行 `006`；扩权会再弹一次属正常 |
| 认证中心已登出、子系统仍能进一小段 | access 短 TTL 内仍有效 + 未吊销 refresh | 预期窗口；IdP 全局登出应吊销 refresh（见 §5） |
| refresh 后旧 refresh 仍能用 | 子系统未覆盖保存新 refresh | 轮换：必须用新返回值覆盖 |
