# 智能家居子系统 — 数据库设计

> PostgreSQL · 会话在 Redis · 设备实时态以 HA 为准，本地存元数据与审计  
> 关联：[架构设计.md](./架构设计.md) · [HA对接设计.md](./HA对接设计.md) · [认证接入设计.md](./认证接入设计.md)

---

## 1. 约定

| 项 | 约定 |
|----|------|
| 主键 | UUID（建议 v7） |
| 时间 | `TIMESTAMPTZ`，默认 `now()` |
| 隔离 | 业务表带 `user_id`（或经 home 归属到 user）；查询必过滤 |
| 字符 | UTF-8 |
| JSON | `JSONB` |
| 不做（P0） | 多租户 RBAC、Timescale 强制依赖 |
| 统计分析 | **必须入库**：时序点 + 日汇总；分析 API **优先读 PG**，不扫 HA |

**Redis 不进 PG：** session、JWKS 缓存、refresh 单飞锁、可选 states 短缓存。

**时序原则（已定）：** HA recorder 默认约 10 天且依赖在线；用电/开时长等分析 **从 HA 增量同步进本库**，报表与曲线（中长期）读 `telemetry_samples` / `daily_device_stats`。详见 [电耗与功率.md](./电耗与功率.md)。

## 2. ER

```
users
  └── homes
        ├── ha_instances          （P0 可仅用环境变量，表 P1）
        ├── rooms
        ├── devices  ──────────── entity_id 绑定 HA
        │     ├── device_state_cache? （可选）
        │     └── daily_device_stats   （按日分析）
        ├── device_action_logs
        ├── sync_cursors          （history 同步水位）
        └── telemetry_samples     （功率/电量/传感器时序）
```

## 3. 表结构

### 3.1 users

本地用户缓存；身份源为 IdP `sub`。

| 列 | 类型 | 约束 | 说明 |
|----|------|------|------|
| id | UUID | PK | |
| sub | TEXT | UNIQUE NOT NULL | IdP JWT `sub` |
| email | TEXT | | |
| name | TEXT | | |
| avatar_url | TEXT | | 可选 |
| last_login_at | TIMESTAMPTZ | | |
| created_at | TIMESTAMPTZ | NOT NULL | |
| updated_at | TIMESTAMPTZ | NOT NULL | |

索引：`sub` 已唯一。

---

### 3.2 homes

自用默认一用户一家庭；预留扩展。

| 列 | 类型 | 约束 | 说明 |
|----|------|------|------|
| id | UUID | PK | |
| user_id | UUID | NOT NULL FK → users ON DELETE CASCADE | 归属 |
| name | TEXT | NOT NULL | 默认「我的家」 |
| is_default | BOOLEAN | NOT NULL DEFAULT true | |
| created_at / updated_at | TIMESTAMPTZ | NOT NULL | |

索引：`(user_id)`；可选部分唯一：每用户仅一个 `is_default=true`（应用层保证即可）。

**P0：** 登录后若不存在 home 则自动创建默认家。

---

### 3.3 ha_instances（P1，P0 可用 env 代替）

| 列 | 类型 | 约束 | 说明 |
|----|------|------|------|
| id | UUID | PK | |
| home_id | UUID | NOT NULL FK → homes CASCADE | |
| name | TEXT | NOT NULL DEFAULT 'default' | |
| base_url | TEXT | NOT NULL | 如 `http://192.168.1.10:8123` |
| token_encrypted | TEXT | NOT NULL | 加密后的 Long-Lived Token，**禁止明文** |
| is_active | BOOLEAN | NOT NULL DEFAULT true | |
| last_ok_at | TIMESTAMPTZ | | 最近探活成功 |
| last_error | TEXT | | 最近错误摘要 |
| created_at / updated_at | TIMESTAMPTZ | NOT NULL | |

唯一：`(home_id, name)`。  
P0：可不建表，读 `HASS_BASE_URL` + `HASS_TOKEN`。

### 3.4 rooms

| 列 | 类型 | 约束 | 说明 |
|----|------|------|------|
| id | UUID | PK | |
| home_id | UUID | NOT NULL FK → homes CASCADE | |
| name | TEXT | NOT NULL | 客厅 / 卧室… |
| sort_order | INT | NOT NULL DEFAULT 0 | |
| ha_area_id | TEXT | | 可选，对应 HA area |
| created_at / updated_at | TIMESTAMPTZ | NOT NULL | |

唯一：`(home_id, name)`。  
索引：`(home_id, sort_order)`。

---

### 3.5 devices（核心）

用户从 HA **纳入**的设备；MVP **1 行 = 1 entity_id**。

| 列 | 类型 | 约束 | 说明 |
|----|------|------|------|
| id | UUID | PK | 本系统设备 ID |
| home_id | UUID | NOT NULL FK → homes CASCADE | |
| user_id | UUID | NOT NULL FK → users | 冗余，便于隔离查询 |
| entity_id | TEXT | NOT NULL | HA `domain.object_id`，小写 |
| domain | TEXT | NOT NULL | 冗余，筛选用 |
| name | TEXT | | 本地显示名；空则用 HA friendly_name |
| room_id | UUID | FK → rooms SET NULL | |
| favorite | BOOLEAN | NOT NULL DEFAULT false | |
| hidden | BOOLEAN | NOT NULL DEFAULT false | 列表默认不展示 |
| sort_order | INT | NOT NULL DEFAULT 0 | |
| icon | TEXT | | 可选覆盖 |
| meta | JSONB | NOT NULL DEFAULT '{}' | 扩展 |
| created_at / updated_at | TIMESTAMPTZ | NOT NULL | |

**约束：**

- `UNIQUE (home_id, entity_id)`  
- `CHECK (entity_id ~ '^[a-z0-9_]+\.[a-z0-9_]+$')`（可按需放宽）

**索引：**

- `(user_id, favorite DESC, sort_order, name)`  
- `(home_id, domain)`  
- `(room_id)` where room_id is not null  
- `(user_id, hidden)`  

**不存：** 实时 `state`（以 HA 为准）；capabilities 运行时计算（可不落库）。

### 3.8 sync_cursors（同步水位 · 分析入库必备）

按 `entity_id + metric` 记录从 HA history 增量拉取进度。

| 列 | 类型 | 说明 |
|----|------|------|
| id | UUID PK | |
| user_id / home_id | UUID | 归属 |
| device_id | UUID FK nullable | 设备删除可空 |
| entity_id | TEXT NOT NULL | |
| metric | TEXT NOT NULL | `power` / `energy` / `state` / `temperature`… |
| last_ts | TIMESTAMPTZ | 已同步到的 HA 时间点 |
| last_success_at | TIMESTAMPTZ | 上次成功 |
| last_error | TEXT | |

唯一：`(home_id, entity_id, metric)`。  
迁移：`002_telemetry_energy.sql`。

---

### 3.9 telemetry_samples（时序点 · **入库主表**）

从 HA history / 定时采样写入；**统计分析与中长期曲线读本表**（非实时扫 HA）。

| 列 | 类型 | 说明 |
|----|------|------|
| id | BIGSERIAL PK | |
| user_id / home_id | UUID NOT NULL | |
| device_id | UUID FK nullable | |
| entity_id | TEXT NOT NULL | |
| metric | TEXT NOT NULL | `power`（W）/ `energy`（kWh）等 |
| ts | TIMESTAMPTZ NOT NULL | 采样时间 |
| num_value | DOUBLE PRECISION | 解析后的数值 |
| state_raw | TEXT | 原始 state |
| unit | TEXT | W / kWh … |
| source | TEXT | `ha_history` / `ha_state` / `estimated` |

唯一：`(entity_id, metric, ts)`（防重复同步）。  
索引：`(entity_id, metric, ts DESC)`、`(home_id, metric, ts DESC)`、`(user_id, ts DESC)`。  

量极大时：按月分区或迁 Timescale hypertable；**P1 先普通表即可**。

---

### 3.10 daily_device_stats（按日汇总 · 分析页主查）

由定时任务根据 `telemetry_samples`（及开关类 state 序列）滚动计算。

| 列 | 类型 | 说明 |
|----|------|------|
| id | UUID PK | |
| user_id / home_id | UUID NOT NULL | |
| device_id | UUID NOT NULL | |
| entity_id | TEXT NOT NULL | |
| stat_date | DATE NOT NULL | 业务日（建议本地时区切日） |
| on_count | INT | 开启次数 |
| on_duration_sec | BIGINT | 开启秒数 |
| energy_kwh | NUMERIC(14,6) | **当日用电** |
| energy_source | TEXT | `meter_diff` / `power_integral` / `mixed` / `none` |
| avg_power_w / max_power_w | NUMERIC | 可选 |
| sample_count | INT | 参与汇总的点数 |
| extra | JSONB | |

唯一：`(device_id, stat_date)`。  
索引：`(user_id, stat_date DESC)`；部分索引 `energy_kwh IS NOT NULL`。

**读路径：** `GET /analytics/*` **默认查本表**；明细曲线查 `telemetry_samples`；HA 仅作同步源。

## 4. Redis 键（非 PG）

| Key | 用途 | TTL |
|-----|------|-----|
| `sh:sess:{sid}` | 登录会话 JSON | 对齐 session 策略 |
| `sh:jwks` | JWKS 缓存 | 10m |
| `sh:refresh_lock:{sid}` | refresh 单飞 | 30s |
| `sh:ha:states` | 可选全量 states 缓存 | 2～5s |
| `sh:idem:{key}` | 控制幂等 | 30s |

Session 字段逻辑：`user_id, sub, access_token, refresh_token, access_expires_at, name, email`（与认证设计一致）。

## 6. 查询模式

### 6.1 我的设备列表

```sql
SELECT * FROM devices
WHERE user_id = $1 AND hidden = false
ORDER BY favorite DESC, sort_order, name;
```

应用层批量拼 HA states（或缓存）→ DeviceView。

### 6.2 纳入设备

```sql
INSERT INTO devices (id, home_id, user_id, entity_id, domain, name, ...)
VALUES (...)
ON CONFLICT (home_id, entity_id) DO NOTHING;
```

### 6.3 归属校验（控制前）

```sql
SELECT id, entity_id, domain FROM devices
WHERE id = $1 AND user_id = $2;
```

### 6.4 写入时序（同步任务）

```sql
INSERT INTO telemetry_samples (user_id, home_id, device_id, entity_id, metric, ts, num_value, unit, source)
VALUES ($1,$2,$3,$4,'energy',$5,$6,'kWh','ha_history')
ON CONFLICT (entity_id, metric, ts) DO NOTHING;
```

### 6.5 分析：某日家庭总用电

```sql
SELECT COALESCE(SUM(energy_kwh), 0)
FROM daily_device_stats
WHERE user_id = $1 AND stat_date = $2 AND energy_kwh IS NOT NULL;
```

### 6.6 分析：设备用电排行（区间）

```sql
SELECT device_id, entity_id, SUM(energy_kwh) AS kwh
FROM daily_device_stats
WHERE user_id = $1 AND stat_date BETWEEN $2 AND $3
GROUP BY device_id, entity_id
ORDER BY kwh DESC NULLS LAST
LIMIT 20;
```

### 6.7 曲线：读入库时序（非 HA）

```sql
SELECT ts, num_value, unit
FROM telemetry_samples
WHERE user_id = $1 AND entity_id = $2 AND metric = 'power'
  AND ts >= $3 AND ts < $4
ORDER BY ts;
```

## 7. 安全与合规

1. `token_encrypted` 使用应用层加密（密钥来自 env/KMS），备份勿明文  
2. `device_action_logs.params` 不写 token；亮度等可记  
3. 删除用户：CASCADE home → devices；日志可保留匿名 entity_id  

---

## 8. 与 PM 库隔离

独立 database（如 `smart_home`）或独立 schema；**不要**与 `pm` / `auth` 混表。  
用户仅通过 IdP `sub` 关联，无跨库 FK。
