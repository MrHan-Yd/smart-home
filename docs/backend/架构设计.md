# 智能家居子系统 — 架构设计

> 定位：**自用**设备管理、实时监控、远程控制、使用分析  
> 路线：**半自研** — Home Assistant 做设备接入层；本系统做业务、认证、分析  
> **后端：Go**（与 ProjectManagement 对齐，见 [技术选型.md](./技术选型.md)）  
> 身份：统一认证中心（OAuth2 授权码 + OIDC，**不自签 Token**）  
> 契约：[子系统接入说明.md](./子系统接入说明.md) · [子系统接入契约.md](./子系统接入契约.md)

---

## 1. 系统定位

| 项 | 说明 |
|----|------|
| 是什么 | 个人智能家居门户：设备列表、开关控制、状态大屏、历史曲线与简单分析 |
| 不是什么 | 替代米家 App 配网；不是厂商协议全家桶；不是 Keep 等封闭健康硬件中枢 |
| 身份 | OAuth 机密客户端；票只来自统一认证中心 |
| 设备接入 | **Home Assistant（HA）** 统一对接小米等主流品牌；本系统只对接 **HA 一套 API** |
| 数据范围 | 自用场景：按用户绑定「家庭/HA 实例」隔离（初期可单用户单 HA） |

## 2. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│                         客户端                                │
│              Web 管理台 / 监控大屏（SPA）                       │
└────────────────────────────┬─────────────────────────────────┘
                             │ HTTPS + Cookie Session
                             ▼
┌──────────────────────────────────────────────────────────────┐
│                    smart-home-service（BFF）                   │
│  OAuth 会话 · 设备域模型 · 控制编排 · 历史同步 · 分析 API      │
└─────┬──────────────┬──────────────┬──────────────┬───────────┘
      │              │              │              │
      ▼              ▼              ▼              ▼
 PostgreSQL        Redis      统一认证中心     Home Assistant
 用户/家庭/         Session     登录发 token     设备状态/控制/
 设备元数据/        JWKS 缓存    JWKS 验签        历史 history
 分析汇总           单飞锁
      │
      │  （可选长期时序）
      ▼
 TimescaleDB / InfluxDB
 传感器时序、用电量等
```

| 组件 | 职责 |
|------|------|
| smart-home-service | 业务 API、OAuth 回调、HA 适配、权限、分析聚合 |
| 统一认证中心 | 唯一 IdP；登录、发 token、刷新、吊销 |
| Home Assistant | 跨品牌设备接入、本地/云控制、状态与 history |
| PostgreSQL | 本地用户缓存、家庭、设备映射、场景元数据、同步游标 |
| Redis | 本地 session、JWKS 缓存、refresh 单飞、控制幂等键 |
| 时序（PG 表） | **`telemetry_samples` + `daily_device_stats`**：从 HA 增量同步，**统计分析读库**（见电耗文档） |
| 客户端 | **Web SPA**（主）；同仓 Vue 经 **Capacitor 出 Android APK**（后置，见 [移动端与APK.md](../frontend/移动端与APK.md)） |

**原则：**

1. **身份**只信认证中心；**设备协议**只信 HA。  
2. 浏览器 **永不** 持有 `client_secret`、HA Long-Lived Token、refresh。  
3. 前端只调本系统 API；本系统服务端再调 HA / IdP。

## 3. 与统一认证中心的关系

完全按 IdP 契约作为**业务子系统**接入（与 ProjectManagement 同模式）：

```
用户访问 smart-home
  → 未登录：302 → IdP /oauth/authorize（state + PKCE）
  → 登录 / 同意
  → 回调本系统 /oauth/callback
  → 服务端 POST IdP /oauth/token 换票
  → JWKS 验签 → 本地 users upsert(sub) → Redis session
  → 业务 API 只认本地 session（或校验 IdP JWT）
```

| 规则 | 说明 |
|------|------|
| 不自签 Token | access / refresh / id_token 只来自 IdP |
| 机密客户端 | `client_secret` 仅后端 |
| 无感刷新 | 子系统单飞 refresh；失败清会话再 authorize |
| 切换系统 | 只清本地 session，跳 `{APP_BASE_URL}/select-system` |
| 登出 | 清本地 + 可选 `/oauth/revoke` |

详情见 [认证接入设计.md](./认证接入设计.md)。

**IdP 侧准备：**

- 管理台注册客户端，例如 `client_id = smart_home`
- `redirect_uris` 精确匹配（开发示例：`http://127.0.0.1:3002/oauth/callback`）
- 可选 `system_routes` 挂到系统选择页
- scopes：`openid profile email`

## 4. 与 Home Assistant 的关系

HA 是**设备中枢**，不是身份源。

```
米家 / 涂鸦 / Matter / Zigbee …
        ↓
 Home Assistant（常开主机）
        ↓  Long-Lived Token（仅服务端）
 smart-home-service
        ↓
 Web（状态、控制、分析）
```

| HA 能力 | 本系统用法 |
|---------|------------|
| `GET /api/states` | 设备实时状态列表 |
| `GET /api/states/{entity_id}` | 单实体详情 |
| `POST /api/services/{domain}/{service}` | 开关、调光、空调等控制 |
| `GET /api/history/period` | 状态变化历史 → 曲线/分析 |
| `GET /api/logbook` | 操作日志（可选） |
| WebSocket API | 实时推送状态变更（推荐后续做） |

**安全：**

- HA Token 只存服务端配置 / 密钥管理，不进前端、不进仓库明文。  
- 控制接口必须先过本系统登录态；再映射到允许的 `entity_id`。  
- HA 尽量内网访问；外网用 VPN / 反代，勿裸奔 8123。

**部署前提：**

- 一台 **7×24** 主机跑 HA（NAS / 小主机 / 树莓派）。  
- 设备先在厂商 App（如米家）配网，再在 HA 加集成。

## 5. 领域模型（逻辑）

```
users (sub = IdP 用户 UUID)
  └── homes（家庭/空间，自用可默认一个）
        ├── ha_instances（HA 连接：base_url、token 引用、状态）
        ├── rooms（房间，可选）
        ├── devices（业务设备：名称、房间、类型）
        │     └── entity_bindings（HA entity_id 映射）
        ├── scenes（场景元数据，执行时可调 HA script/scene）
        └── sync_cursors（历史同步水位）
```

| 概念 | 说明 |
|------|------|
| device | 用户「纳入」的设备；MVP 为 1 设备 ↔ 1 entity |
| entity_id | HA 原生 ID，如 `light.living_room` |
| capability | 能力抽象：on_off / brightness / climate …（驱动 UI 与 actions） |
| TypeProfile | domain → 默认能力集；未注册 domain 仍可添加为只读 |
| telemetry | 时序点：时间 + entity + 指标 + 值 |

**多类型添加与扩展：** [设备类型与接入设计.md](./设备类型与接入设计.md)（发现池 → 纳入 → 能力注册表 → 分期实现控制）。

## 6. 核心链路

### 6.1 登录

见 §3 与 [认证接入设计.md](./认证接入设计.md)。

### 6.2 读状态

```
Web → GET /api/v1/devices
    → service 鉴权 session
    → HA GET /api/states（或本地缓存 + 增量）
    → 映射为统一 DTO 返回
```

### 6.3 控制

```
Web → POST /api/v1/devices/{id}/actions  { action, params }
    → 鉴权 + 校验设备归属
    → 解析 HA domain/service/entity_id
    → HA POST /api/services/...
    → 写操作审计（可选）
    → 返回新状态（或触发 WS 推送）
```

控制幂等：可选 `Idempotency-Key` + Redis 短 TTL，避免双击连发。

### 6.4 历史与分析

```
同步任务（定时 / 手动）
  → HA /api/history/period?filter_entity_id=...
  → 写入时序库或 PG 汇总表
  → Web 图表：日开时长、次数、温湿度曲线、用电（有传感器时）
```

| 阶段 | 策略 |
|------|------|
| MVP | 前端请求时透传查 HA history（实现快，依赖 HA 在线） |
| 增强 | 后台增量同步到自有库，报表不拖垮 HA，可超 HA 默认保留期 |

HA 默认详细 history 约 10 天；长期分析需自建同步或调长 recorder。

### 6.5 实时（后续）

```
HA WebSocket → smart-home-service 订阅 state_changed
             → 按 home 推送到已登录 Web（本系统 WebSocket）
```

MVP 可用短轮询 `GET /api/v1/devices`。

## 8. API 前缀（摘要）

| 路径 | 说明 |
|------|------|
| `/oauth/login` | 跳转 IdP authorize |
| `/oauth/callback` | code 换票、建 session |
| `/oauth/logout` | 清本地会话 |
| `/api/v1/me` | 当前用户 |
| `/api/v1/homes` | 家庭 / HA 绑定（自用可默认） |
| `/api/v1/devices` | 设备列表与状态 |
| `/api/v1/devices/{id}/actions` | 控制 |
| `/api/v1/history` | 历史曲线 |
| `/api/v1/analytics/*` | 使用分析汇总 |
| `/api/v1/ws` | 实时状态（后续） |

所有 `/api/v1/*` 必须登录；HA 凭据不出现在响应中。

## 9. 配置项（逻辑）

| 配置 | 说明 |
|------|------|
| AUTH_BASE / OAUTH_* | 认证中心与客户端（见认证接入设计） |
| OAUTH_REDIRECT_URI | 如 `http://127.0.0.1:3002/oauth/callback` |
| SESSION_* | Cookie 名、TTL、Secure |
| HASS_BASE_URL | 如 `http://192.168.x.x:8123` |
| HASS_TOKEN | Long-Lived Access Token（密钥） |
| HASS_TIMEOUT / 重试 | 调用 HA 超时与退避 |
| DATABASE_URL / REDIS_URL | 业务库与会话 |

多 HA 实例时：token 按 `ha_instances` 存库（加密），不单靠全局环境变量。

## 10. 安全设计

| 项 | 措施 |
|----|------|
| 身份 | OAuth2 + PKCE + state；JWKS RS256；secret 仅服务端 |
| 会话 | HttpOnly Cookie；空闲超时 + 最长 TTL；refresh 单飞 |
| HA | Token 服务端；内网优先；控制前校验设备归属 |
| 日志 | 禁止打印 code / access / refresh / HA token |
| 生产 | HTTPS；`COOKIE_SECURE`；统一 `127.0.0.1` 与域名，勿混 localhost |

## 11. 阶段规划

| 阶段 | 内容 |
|------|------|
| **P0** | IdP 接入（login/callback/session）；HA states 列表；单设备开关控制 |
| **P1** | 房间/备注；history 曲线；操作审计；系统选择页路由 |
| **P2** | WebSocket 实时；历史同步入库；用电/开时长分析报表 |
| **P3** | 多 HA / 场景编排；权限细分；移动端适配 |

**明确不做（初期）：** Keep 体脂秤等无开放生态设备；全自研厂商协议适配。

## 14. 总结

```
用户 ──SSO──► 统一认证中心
  │
  └── session ──► smart-home-service ──► Home Assistant ──► 米家等设备
                      │
                      ├── PostgreSQL（元数据 / 映射）
                      ├── Redis（会话）
                      └── 时序库（可选，分析）
```

- **认证**：统一认证中心  
- **设备**：Home Assistant  
- **产品能力**：本系统 Web 的管理、控制、监控、分析  

下一步可拆：认证接入细节落地清单 → HA 适配接口草案 → 库表设计 → P0 接口与前端页面。
