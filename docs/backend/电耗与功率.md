# 智能家居子系统 — 电耗与功率

> 结论：**能**，但只读 Home Assistant 已暴露的功率/电量实体；本系统不直连电表、不自研采集协议。  
> 关联：[HA对接设计.md](./HA对接设计.md) · [功能设计.md](./功能设计.md) · [设备类型与接入设计.md](./设备类型与接入设计.md)

## 1. 结论一览

| 问题 | 答案 |
|------|------|
| HA 能否获取电耗？ | **能**，前提是 HA 里已有对应 **sensor**（插座/电表/集成提供） |
| 本系统如何拿？ | 与其它设备相同：服务端调 HA REST，**不**让浏览器直连 HA |
| P0 已有能力 | 可将功率/电量 sensor **纳入**，列表/详情 **只读展示当前值** |
| 尚未做 | 用电汇总、曲线报表、电费估算（见分期与任务） |
| 没有实体怎么办？ | 先在 HA 安装智能插座/电表集成，再回到本系统「添加设备」 |

## 2. HA 侧常见实体

| 含义 | 典型 entity 示例 | `device_class` | 单位（常见） | 说明 |
|------|------------------|----------------|--------------|------|
| 瞬时功率 | `sensor.xxx_power` | `power` | W / kW | 当前功率 |
| 累计电量 | `sensor.xxx_energy` | `energy` | kWh / Wh | 累计用电，看 `state_class` |
| 电压/电流 | `sensor.xxx_voltage` 等 | `voltage` / `current` | V / A | 可选，分析辅助 |

**State 示例（功率）：**

```json
{
  "entity_id": "sensor.plug_living_power",
  "state": "12.5",
  "attributes": {
    "unit_of_measurement": "W",
    "device_class": "power",
    "state_class": "measurement",
    "friendly_name": "客厅插座功率"
  }
}
```

**State 示例（电量）：**

```json
{
  "entity_id": "sensor.plug_living_energy",
  "state": "18.42",
  "attributes": {
    "unit_of_measurement": "kWh",
    "device_class": "energy",
    "state_class": "total_increasing",
    "friendly_name": "客厅插座电量"
  }
}
```

### 2.1 物理设备与多 entity

同一插座在 HA 常拆成：

- `switch.xxx` — 开关  
- `sensor.xxx_power` — 功率  
- `sensor.xxx_energy` — 累计电量  

本系统 P0：**分别添加**为多条设备；P3 再考虑「一设备多 entity 聚合」。

### 2.2 如何确认家里有没有

1. HA 开发者工具 → 状态：搜 `power` / `energy` / 功率 / 电量  
2. 看 attributes 的 `device_class` 是否为 `power` 或 `energy`  
3. 无则：在 HA 添加米家/涂鸦/Shelly/电表等集成后再查

## 3. 本系统职责边界

| 做 | 不做 |
|----|------|
| 发现并纳入 `sensor`（含功率/电量） | 直连厂商电表协议 |
| 展示当前 state + unit | 替代 HA 配网 |
| **时序/汇总入库**，分析读 PG | 分析接口长期直扫 HA history |
| 从 HA **增量同步** power/energy | 强制所有家都有电表 |
| 仅操作已纳入 entity | 前端持有 HA Token |

数据路径（**已定：分析走库**）：

```
智能插座/电表 → HA 集成 → sensor.*
       │
       ▼  定时/手动 sync（history 增量）
  telemetry_samples（点） + daily_device_stats（日汇总）
       │
       ▼
  smart-home-service 分析 API → Web 图表 / 排行 / KPI
```

实时当前值：仍可 `GET /api/states` 拼 DeviceView；**统计与历史曲线以库为准**。

## 4. 能力识别（实现约定）

发现与 DeviceView 时，对 `domain=sensor`：

| 条件 | 建议 capability / 展示 |
|------|------------------------|
| `device_class=power` | `numeric_sensor` + 标签「功率」；`primary_display` 带 W/kW |
| `device_class=energy` | `numeric_sensor` + 标签「电量」；`primary_display` 带 kWh |
| 其它数值 sensor | 通用数值展示（温湿度等同） |

`control_level` 一律 **`read_only`**（不可 `turn_on`）。

可选扩展（P1+）：

- 列表筛选：`device_class=power|energy`  
- 详情页强调 unit / state_class  
- 历史：`GET /api/history/period` 透传（与温湿度同一套）

## 5. 分期

| 阶段 | 内容 |
|------|------|
| **P0（当前）** | 纳入功率/电量 sensor，只读当前值；**表结构就绪**（`002_telemetry_energy.sql`） |
| **P1** | **同步入库** + 曲线读库；补历史空洞时可回源 HA 一次 |
| **P2** | 日汇总任务 + 分析 API（KPI/排行/用电）全读 `daily_device_stats` |
| **P3** | 组合设备；电费单价；分区/Timescale（量上来再上） |

### 5.1 汇总口径（入库后计算）

| 有 `energy`（total_increasing） | **优先**写入 metric=`energy`；日用电 = 当日末累计 − 当日初累计（处理回零） |
| 仅有 `power`（measurement） | 写 metric=`power`；日用电 = 梯形/矩形积分 → kWh，`energy_source=power_integral` |
| 无相关 sensor | 不写 energy 汇总；UI 降级 |

电费：`SUM(energy_kwh) × 单价`（单价可放 `homes.meta` 或设置，P2+）。

### 5.2 同步策略（实现约束）

| 项 | 建议 |
|----|------|
| 触发 | 定时（如 5～15min）+ 手动「同步能耗」 |
| 范围 | 仅 **已纳入** 且 domain/metric 为 power/energy（及后续温湿度）的 entity |
| 增量 | `sync_cursors.last_ts` → HA `history/period` → upsert `telemetry_samples` |
| 日汇总 | 每日滚动 / 同步后重算近 2 日 `daily_device_stats` |
| 保留 | 点表建议 ≥90 天（可配置清理）；日汇总长期保留 |
| 失败 | 记 `sync_cursors.last_error`，不阻断控制类 API |
