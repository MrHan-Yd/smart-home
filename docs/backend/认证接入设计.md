# 智能家居子系统 — 认证接入设计

> 契约原文（仓库）：`UnifiedAuthentication/docs/backend/开发/子系统接入契约.md`  
> 副本：[子系统接入契约.md](./子系统接入契约.md) · [子系统接入说明.md](./子系统接入说明.md)  
> 总体架构：[架构设计.md](./架构设计.md)

---

## 1. 原则

1. Token **只**由认证中心 `/oauth/token` 颁发  
2. 机密客户端；`client_secret`、refresh 仅服务端  
3. BFF：HttpOnly Cookie + Redis session  
4. refresh 单飞 + 轮换覆盖  
5. `redirect_uri` 与 IdP 白名单**精确一致**  
6. **不**用 HA Token 做用户登录；HA 与用户身份解耦  

---

## 2. 配置

| 配置 | 说明 | 开发示例 |
|------|------|----------|
| AUTH_BASE | 浏览器/服务端访问 IdP 根 | `http://127.0.0.1:5173` 或 `:3000` |
| OAUTH_CLIENT_ID | 客户端 ID | `smart_home` |
| OAUTH_CLIENT_SECRET | 仅服务端 | 管理台创建时保存 |
| OAUTH_REDIRECT_URI | 回调 | `http://127.0.0.1:3002/oauth/callback` |
| OAUTH_ISSUER | = JWT `iss`，无尾斜杠 | 常与 `APP_BASE_URL` 一致 |
| OAUTH_SCOPES | | `openid profile email` |
| SESSION_* | Cookie 名、TTL、Secure | 空闲 2h / 最长对齐 refresh |

**三处 redirect 必须一致：** IdP 白名单 · 环境变量 · authorize 请求参数。

---

## 3. 流程

```
/oauth/login
  → 生成 state + PKCE verifier
  → 302 IdP /oauth/authorize

IdP：登录 →（首次）同意 → code

/oauth/callback?code&state
  → 校验 state
  → POST IdP /oauth/token（code + verifier + secret）
  → JWKS 验签 access（iss / aud / exp / RS256）
  → upsert users by sub
  → Redis session（user_id, sub, access, refresh, exp, 资料）
  → 302 前端完成页 / 首页（写 Cookie）

业务 API
  → Cookie session
  → 可选：access 将过期则单飞 refresh
  → 再调 HA（与用户 token 无关）
```

无感刷新：access 剩余 &lt; 60s 或业务 401 → 服务端 refresh 单飞 → 失败清会话 → 重新 login。

登出：清 session；可选 IdP `/oauth/revoke`。  
切换系统：只清本地 session → `{APP_BASE_URL}/select-system`。

---

## 4. JWT 校验

1. 缓存 `GET {AUTH_BASE}/jwks.json`  
2. RS256 验签  
3. `iss` == OAUTH_ISSUER  
4. `aud` == client_id  
5. `exp`（clock skew ≤ 60s）  
6. 取 `sub` → 本地用户  

开发期 JWKS 不可达时可临时 userinfo 兜底（`STRICT_JWT=false`），生产必须严格 JWKS。

---

## 5. Session 字段（逻辑）

| 字段 | 说明 |
|------|------|
| user_id | 本地用户主键 |
| sub | IdP 用户 UUID |
| access_token | 仅服务端使用（若需调需鉴权的 IdP API） |
| refresh_token | 仅服务端 |
| access_expires_at | 触发无感刷新 |
| name / email | 展示缓存 |

不把 refresh / HA token 发给浏览器。

---

## 6. 与设备权限

| 层 | 鉴权 |
|----|------|
| 用户是否登录 | IdP + 本地 session |
| 能否操作某设备 | 本系统：设备是否属于该用户的 home |
| 设备是否真实可控 | HA Token + entity 存在 |

自用单用户阶段：登录即可操作已绑定 HA 下全部实体；后续可加房间/设备 ACL。

## 7. IdP 注册清单

- [ ] `POST /admin/clients` 创建 `smart_home`（或 SQL 种子）  
- [ ] `redirect_uris` = 本系统 callback  
- [ ] `pkce_required=true`，grants 含 `authorization_code` + `refresh_token`  
- [ ] （可选）`system_routes` 入口 URL  
- [ ] 迁移含 `user_consents`（同意页）  
- [ ] 联调：authorize → code → token → userinfo → refresh  

---

## 8. 安全清单

- [ ] PKCE + state  
- [ ] secret / refresh / HA token 不出前端  
- [ ] 日志不打 code/token  
- [ ] refresh 单飞  
- [ ] 生产 HTTPS + Secure Cookie  
- [ ] 勿混用 `localhost` 与 `127.0.0.1`  

---

## 9. 实现检查清单

- [ ] refresh 单飞  
- [ ] users upsert by sub  
- [ ] 保护 `/api/v1/*`  
- [ ] 切换系统跳 select-system（不清 IdP SSO）
