# 智能家居子系统 — 前端技术选型

> 后端：[../backend/技术选型.md](../backend/技术选型.md)（Go BFF）  
> 架构：[../backend/架构设计.md](../backend/架构设计.md)  
> 对齐：ProjectManagement 前端选型（Vue 业务子系统统一栈）

---

## 1. 结论（一览）

| 项 | 选型 |
|----|------|
| 框架 | **Vue 3**（Composition API + `<script setup>`） |
| 语言 | **TypeScript** |
| 构建 | **Vite**（最新稳定） |
| 路由 | **Vue Router** |
| 状态 | 优先 **Composable**；跨页复杂状态再 **Pinia** |
| 样式 | **Tailwind CSS** |
| 组件 | **shadcn-vue**（可拷贝源码，非企业中后台皮） |
| 图标 | `lucide-vue-next`（与 shadcn 一致） |
| 图表 | **ECharts**（vue-echarts）— 历史曲线 / 分析 |
| 请求 | `fetch` 封装 或 `ofetch`；`credentials: 'include'` |
| 实时（P2） | 原生 **WebSocket** 连本系统 `/api/v1/ws`（不直连 HA） |
| 部署 | **SPA**；静态资源 + 反代到 Go |
| 移动端（已定方向） | **同一套 Vue**；日常响应式 Web；需要独立安装包时 **Capacitor → Android APK**（见 [移动端与APK.md](./移动端与APK.md)） |

**明确不用：**

- Element Plus / Ant Design Vue / TDesign 默认企业皮  
- 前端存 access / refresh / HA Token  
- 浏览器直连 Home Assistant  
- Nuxt/Next（已有 Go BFF，无需 SSR 抢会话）  
- 与认证中心前端强绑 Naive（IdP 用 Naive 可；**业务子系统跟 PM 用 Vue+Tailwind+shadcn**）  
- **另起 Flutter / React Native / 独立 App 前端仓库**（自用不划算；APK 在现有 `frontend` 内套壳）  
- **依赖夸克等浏览器的 PWA「安装应用」** 作为主交付（支持差；卸 Chrome 后 PWA 也常失效）

---

## 2. 选型理由

### 2.1 与 PM / 多子系统一致

| 系统 | 前端栈 |
|------|--------|
| 统一认证中心 | Vue + Naive（登录/同意/系统选择，已定） |
| ProjectManagement | Vue 3 + Vite + TS + Tailwind + shadcn 路线 |
| **smart-home** | **同 PM**，降低切换成本，组件/请求/鉴权习惯一致 |

IdP 与业务子系统视觉可以不同；**业务子系统之间**保持同一套更划算。

### 2.2 Vue 3 + Vite + TS

- 页面：设备列表、控制、监控、历史/分析，SPA 足够  
- TS 对齐后端 DTO / 错误码  
- Vite 开发体验与现有仓一致  

### 2.3 shadcn-vue + Tailwind

- 观感偏现代产品，非「纯表格中后台」  
- 控制面板、卡片、开关、Dialog 易定制  
- 响应式：侧栏（桌面）/ 底栏或抽屉（移动）  

### 2.4 图表单独选型

智能家居强依赖曲线与统计：

| 库 | 结论 |
|----|------|
| **ECharts** | **采用**：曲线、柱状、仪表盘资料全，中文社区熟 |
| Chart.js | 轻，复杂多轴/大数据略弱 |
| uPlot | 极轻时序，定制成本高，P2 可考虑嵌入 |

P0 可无图表；P1 上 ECharts 即可。

### 2.5 状态

| 数据 | 建议 |
|------|------|
| 当前用户 | `useAuth` composable |
| 设备列表/筛选 | `useDevices`；轮询或后续 WS 写入 |
| 房间/布局偏好 | 本地 composable 或 Pinia 轻量 store |
| 全局 Toast | shadcn Toast，不必上重型 UI 框架 |

实时推送进 P2 后再评估是否用 Pinia 做「设备状态总线」。

## 3. 与后端协作

```
浏览器（Vue SPA）
  │  credentials: 'include'（Cookie 会话）
  ▼
同源或 Vite/Nginx 反代
  ├── /oauth/*   → Go smart-home-service（login/callback/logout）
  ├── /api/v1/*  → Go（设备/控制/历史/分析）
  └── /          → 前端 dist
         │
         ✗ 不直连 HA :8123
         ✗ 不直调 IdP /oauth/token（无 secret）
```

| 约定 | 说明 |
|------|------|
| 鉴权 | HttpOnly Cookie（如 `sh_sid`）；**禁止** localStorage 存 token |
| 未登录 | 前端发现 401 → 跳转 `GET /oauth/login?return_to=...`（由后端 302 IdP） |
| 切换系统 | 清本地观感状态后跳 IdP `{APP_BASE_URL}/select-system` |
| 控制 | 只调 `POST /api/v1/devices/{id}/actions`，不拼 HA service |

开发代理示例（Vite）：

```ts
// vite.config.ts 示意
server: {
  port: 5175,
  proxy: {
    '/oauth': 'http://127.0.0.1:3002',
    '/api': 'http://127.0.0.1:3002',
  },
}
```

## 4. 页面与路由（建议）

| 路由 | 说明 | 阶段 |
|------|------|------|
| `/` | 总览 / 设备墙 | P0 |
| `/devices` | 设备列表 + 筛选 | P0 |
| `/devices/:id` | 详情与控制 | P0 |
| `/history` | 历史曲线 | P1 |
| `/analytics` | 使用分析 | P2 |
| `/settings` | HA 绑定展示、偏好（敏感 token 不展示明文） | P1 |
| `/oauth/complete` | 登录回跳落地（若后端采用） | P0 |

布局：顶栏（用户 / 切换系统 / 登出）+ 主内容；桌面可房间侧栏。

## 5. 目录约定（建议）

```
frontend/                    # 唯一前端工程（Web + 未来 APK 同源）
├── public/
├── src/                     # 全部业务 UI（Vue）
│   ├── api/
│   ├── assets/
│   ├── components/
│   ├── composables/
│   ├── layouts/
│   ├── lib/
│   ├── router/
│   ├── types/
│   ├── views/
│   ├── App.vue
│   └── main.ts
├── android/                 # Capacitor 生成（打包 APK 时，非现在必有）
├── capacitor.config.ts      # 打包阶段再加
├── index.html
├── package.json
├── vite.config.ts
└── tsconfig*.json
```

包管理：与认证中心 / 习惯一致可用 **pnpm**。

**移动端不新建第二前端项目**；APK = 本目录 `build` → Capacitor 同步 → Android 工程出包。

## 10. 移动端结论（摘要）

| 问题 | 结论 |
|------|------|
| Vue 能否做 App？ | **能**；页面仍是 Vue，壳是 Capacitor |
| 是否新开 App 项目？ | **否**；在现有 `frontend/` 内做 |
| 安卓 / iOS | 先 **Android APK**；iOS 需 Mac，非现阶段重点 |
| 仅浏览器 | 响应式 Web + 收藏即可；不依赖「装 PWA」 |
| 时机 | **Web 登录与控制稳定后再**引入 Capacitor |

详情：[移动端与APK.md](./移动端与APK.md)
